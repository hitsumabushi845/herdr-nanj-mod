# Agent ごとのスレッドとタブの設計

mod `nanj` のスレッドを Agent ごとに分け、上部のタブで切り替えられるようにする。元の設計は `2026-11-16-nanj-thread-design.md` にあり、この文書はその「スレッドの形」と「表示」を置き換える。ほかの節（きっかけ、呼び出しの上限、口調、設定）は元の設計のままとする。

## 目的

全 Agent が 1 本のスレッドに書き込む形を 4 日間使ったところ、複数の Agent の話が混ざって流れを追いにくかった。Agent ごとにスレッドを分け、見たい Agent の話だけを読めるようにする。

## ゴール

- 1 本のスレッドには 1 つの Agent のレスと、そのレスへの野次馬の突っ込みだけが流れる。
- 起動している Agent のスレッドが上部にタブで並び、クリックで切り替えられる。
- 見ていないスレッドにレスが付いたことが、タブでわかる。
- それぞれのスレッドは、タスクが替わっても同じ 1 本のまま続く。

## やらないこと

- 全 Agent のレスをまとめて読むタブ。
- Agent をまたいだ野次馬の突っ込みや掛け合い。
- 終了した Agent のスレッドを読む画面。

## 避けること

- 別の Agent の話が 1 本のスレッドに混ざる。
- 利用者が選んでいないのに、表示するスレッドが切り替わる。
- 移行で、いまのスレッドのレスを失う。

## 検討した作り方

1. 端末ごと。Agent の端末 1 つを 1 本のスレッドとする。同じ space に Agent が 2 つあっても混ざらない。
2. Herdr のタブごと。同じタブで Agent を起動し直してもスレッドが続く。1 つのタブをペインで分けて Agent を 2 つ動かすと、話が混ざる。

利用者は 1 の端末ごとを選んだ。話が混ざらないことを確実に守れるためである。

## 利用者が決めたこと

- スレッドを起動している Agent ごとに分ける。
- スレッドの一覧を、画面の上部にタブの形で出す。
- 1 本のスレッドの単位は端末とする。
- 1 本にまとめた形は、話が混ざってわかりづらいのでやめる。

## 設計

この節は設計者が決めた内容である。利用者には要点を伝えてあり、実物を見てから変えてよい。

### スレッドの単位

- スレッドのキーは `<端末のアドレス>@<端末の作成時刻>` とする（例: `t16@1700000000000`）。アドレスが別の端末に使い回されても、前のスレッドに書き込まないためである。
- 作成時刻は `hc get <端末> --json` の `created_ms` から取り、端末ごとに 1 回だけ読んで覚える。`agents()` と `hc ls --json` には作成時刻がない。作成時刻が取れない間は、その Agent のスレッドを作らず、レスも作らない。次の見回りでもう一度読む。
- 実機では、Agent は fish の端末の中で動く。同じ端末で Agent を終了して起動し直しても、アドレスと作成時刻は変わらないので、同じスレッドが続く。新しいスレッドになるのは、新しい端末（新しいタブやペイン）で Agent を起動したときである。利用者には「起動し直すと新しいスレッドになる」と伝えてあったので、この点は訂正して伝える。
- スレッドは、その Agent に最初のレスが付くときに作る。
- スレタイ、レス番号、30 分ごとのスレタイの付け直しは、スレッドごとに持つ。
- 「次スレ」ボタンは表示中のスレッドだけを空にする。自動では替えない。
- 野次馬はそのスレッドのレスにだけアンカーを付ける。モデルに渡す直近のレス 10 件も、そのスレッドのものとする。
- 雑談は、作業中の Agent のうち最後のレスがいちばん古い Agent のスレッドに、野次馬のレスとして書く。間隔は全体で 10 分に 1 回のままとする。
- 呼び出しの上限は全スレッドの合計のままとする。

### 表示

```
[●sample-api 3] [○herdr-nanj-mod] [○sample-web]
【悲報】テストが 3 件だけ通らない        停止  次スレ
実況中
---------------------------------------------------------
41 sample-api 2026/11/20(金) 10:12:03 ID:t16
   モックの戻り値を直したら 3 件通ったで
42 風吹けば名無し 2026/11/20(金) 10:12:03 ID:x8Kq2
   >>41 残りの 2 件は別の原因やろ
```

- いちばん上にタブの列を置く。タブはいま起動している Agent（`agents()` が返し、`exclude_spaces` に入っていないもの）に 1 つずつ出す。並びは `agents()` の順とする。
- タブの文字は Agent の名前（元の設計のコテハン）とする。左に状態の印を付け、色は working、blocked、done、idle でテーマの同じ名前の色を使う。
- 表示中でないスレッドに未読のレスがあれば、タブの右に未読の数を出す。
- タブが幅に収まらないときは、タブの列を横にスクロールできる。
- まだレスのない Agent のタブを選ぶと、スレタイの位置に「スレ立て待ち」と出す。
- 起動している Agent が 1 つもないときは、タブの列を出さず、「起動している Agent がありません」と出す。
- Agent 本人の名前の色はスレッドを作った順に 8 色を割り当てる。タブの名前にも同じ色を使う。

### タブの選択と未読

- タブはクリックでだけ切り替わる。Herdr で別の Agent に移っても、スレッドは切り替えない。
- 選んだタブは `shared("nanj.tab")` にキーで覚える。
- 覚えたキーの Agent が起動していないとき（最初の起動と、表示中の Agent が終了したとき）は、そのときの先頭のタブを選び、そのキーを覚え直す。以後は、利用者がクリックするか、その Agent が終了するまで替えない。終了した Agent があとで戻っても、表示は戻さない。`agents()` の順が変わっても、表示中のスレッドは替えない。
- 既読の位置は `shared("nanj.seen")` に `{キー: 最後に見たレス番号}` で持つ。表示中のスレッドは、レスが付くたびに既読にする。
- mod のコピーが 2 つ以上あるとき、選んだタブと既読の位置はコピーの間で共通とする。

### 保存

- フォルダは `~/.config/herdr-nanj` のままとする。
- スレッドは 1 本を 1 ファイルにして `threads/<キー>.json` に置く。キーの `/` は `_` に置き換える。中身はいまのスレッドの形に、キー、端末のアドレス、名前、色の番号を足したものとする。1 ファイルにまとめないのは、`readTextFile` が 1 MiB までしか読めないためである。
- スレッドの一覧は `index.json` に置き、キー、端末のアドレス、名前、色の番号、最後のレスの時刻を持つ。
- 保存するレスはスレッドごとに新しいほうから 1000 件までとする。
- 生成役のコピーだけが書き込む。書き込んだら `shared("nanj.rev")` で、どのスレッドが変わったかを他のコピーに伝える。

### 終了した Agent のスレッド

- 起動していない Agent のスレッドは、タブに出さない。ファイルは残す。
- 起動していない Agent のスレッドは、最後のレスから 7 日たったら、ファイルと一覧の項目を消す。`agents()` が一時的に空を返しても消えないよう、起動していないことだけでは消さない。

### いまのスレッドからの移行

- `thread.json` があり `index.json` がないときに、1 回だけ移行する。
- Agent 本人のレスは、その端末のスレッドに入れる。端末がいま起動していれば、その作成時刻でキーを作る。起動している端末の作成時刻が 1 つでも取れない間は、移行を始めず、次の見回りでやり直す。
- いま起動していない端末のレスは `<アドレス>@0` のスレッドに入れる。このスレッドはタブに出ず、7 日後に消える。終了した Agent のスレッドの扱いと同じである。
- 野次馬のレスは同じ時刻に付いた Agent 本人のレスと同じスレッドに入れる。同じ時刻の Agent 本人のレスがない野次馬のレス（雑談）は捨てる。
- レス番号は元のまま残す。アンカーの指す先を変えないためである。移行したスレッドの番号は連番にならない。
- スレタイは付けない。次のレスと一緒にモデルが付ける。
- 移行が済んだら、`thread.json` を `thread.json.migrated` に名前を変えて残す。

### 変わるモジュール

- `thread.js`: キーと名前を持つスレッド、一覧、移行の関数。
- `triggers.js`: 雑談のきっかけに Agent のアドレスを持たせる。
- `engine.js`: スレッドを 1 本から複数に替える。対象の Agent のスレッドを読み、書き、古いスレッドを消す。
- `main.js`: タブの列、選択、未読、スレッドごとの読み書き。
- `prompt.js` と `budget.js` は変えない。

## 作る側に任せること

- タブの見た目（余白、選択中の示し方、未読の数の形）。
- 一覧とスレッドのファイルの書き込みの順序と、片方だけ書けたときの扱い。条件は、一覧にないスレッドのファイルが残っても表示が壊れないことである。
- 起動していない Agent のスレッドを、メモリに読み込むかどうか。
- 古いスレッドを消す処理を走らせる頻度。

## 完成の確認

- vitest と `herdr-app check` が通る。
- 実機で Agent を 2 つ動かし、それぞれのタブに、その Agent のレスと野次馬のレスだけが付く。
- 表示中でないスレッドにレスが付くと、タブに未読の数が出る。タブを選ぶと消える。
- Herdr で別の Agent に移っても、表示中のスレッドが変わらない。
- 移行のあと、Agent ごとのスレッドのレスの合計と、捨てた雑談のレスの数の和が、移行の直前の `thread.json` のレスの数と同じになる。`thread.json.migrated` が残っている。
- 同じ端末で Agent を終了して起動し直すと、同じスレッドに続きのレスが付く。
- 「次スレ」を押すと、表示中のスレッドだけが空になる。
