# なんJ 実況スレ mod の設計

Herdr app の画面に 2ch のスレッド風の表示を出し、稼働している Agent の作業をなんJ 口調のレスで実況する mod を作る。mod の名前は `nanj` とする。

## 目的

Agent の実装中は待ち時間が長い。その間に Agent が何をしているかを、ユーモアを交えたレスとして眺められるようにする。作業の途中でわかった新しい事実や技術的な知見も、レスとして流れてくるようにする。

## ゴール

- 稼働中の Agent ごとに、進捗、発見、感想がなんJ 口調のレスとして投稿される。
- 待ちが長いときは、経過時間に触れたレスや野次馬のレスが付き、待っている状況を笑って眺められる。
- Agent の画面に出た新しい事実や知見が、【朗報】【悲報】【速報】のような見出し付きのレスになる。
- Agent 側の設定を変えずに、Claude Code でも Codex でも動く。

## やらないこと

- 人がスレッドに書き込む機能。
- Agent 自身に書き込ませる仕組みと、Claude Code のフックから材料を取る仕組み。画面から拾いきれないと感じたら、後から足す。
- 過去スレの一覧や検索。

## 避けること

次のどれかが起きたら、動いていても失敗とみなす。

- Agent の作業を妨げる。mod は Agent の端末にキー入力やテキストを送らない。読むだけにする。
- レス生成の呼び出しが際限なく増える。
- 画面にあった認証情報（トークン、鍵、パスワード）がレスに載る。
- 差別的な表現、性的な表現、実在の人物への中傷がレスに載る。
- 画面にない技術的な事実を、発見として書く。

## 制約

- mod は `mods/<name>/main.js` に置く JavaScript で、gpui-kit の要素で UI を描く。HTML、CSS、Node の API、`setTimeout` は使えない。型の定義は `~/.config/herdr-app/herdr.d.ts` と `gpui-kit.d.ts` にあり、ガイドは同じフォルダの `AGENTS.md` にある。
- 繰り返しの処理は `cx.timer`、外部コマンドの実行は `exec`、Agent の一覧は `agents()`、画面の取得は `hc read <端末> --lines <行数>` を使う。
- `exec` の出力は 8 MiB まで、タイムアウトは既定で 30 秒。
- 再描画は窓全体に及ぶので、アニメーションのためにタイマーで `cx.notify()` を呼ばない。
- レス生成には手元の `claude` コマンド（`claude -p`、モデルは Haiku）を使う。`--bare` は API キーでの認証を前提にするので使わない。
- 画面の内容は利用者の Claude アカウントを通じてモデルに送られる。利用者はこれを了承している。
- 変更のたびに `herdr-app check <mod のフォルダ>` を通す。

## 検討した作り方

1. 実況方式。mod が Agent の画面を定期的に読み、差分を小さいモデルに渡してレスにする。Agent 側の設定が要らず、作業を妨げず、Agent の種類を問わない。画面に出た内容しか拾えず、レス生成のたびにモデルを呼ぶ。
2. 自己投稿方式。Agent 自身がコマンドで書き込む。発見を当事者が正確に書けるが、全 Agent に指示を仕込む必要があり、本業の文脈とトークンを使い、書き込みを忘れることがある。
3. フック方式。Claude Code のフックで会話ログを拾い、小さいモデルがレスにする。画面より正確な材料が取れるが、Claude Code 専用で、`settings.json` へのフックの追加が要る。

利用者は 1 の実況方式を選んだ。待ち時間をユーモア込みで眺めるという目的に、Agent の手を止めない方式が合うためである。

## 利用者が決めたこと

- 表示は 2ch のスレッド風にする。
- 流れてくる内容は進捗、感想、ときどきの雑談、作業中にわかった新しい事実や技術的な知見とする。
- 待ちの状況をユーモアを交えて見られるようにする。
- 作り方は実況方式とする。
- 具体的な中身は、最初は作る側に任せる。口調はインターネット上のなんJ のスレッドを元にする。

## 設計

この節は、任された範囲について設計者が決めた内容である。利用者は実物を見てから変えてよい。

### スレッドの形

- スレッドは窓全体で 1 本とし、全 Agent が同じスレッドに書き込む。
- 投稿者は 2 種類とする。1 つは Agent 本人で、一人称（ワイ）で自分の作業を語る。もう 1 つは野次馬で、Agent のレスにアンカー（`>>3`）を付けて突っ込む。
- Agent 本人は、どの Agent かが見てわかるようにコテハンで書き込む。名前は space の名前とし、同じ space に Agent が 2 つ以上あるときは「space の名前/tab の名前」とする。ID は端末のアドレス（`ID:t17`）とする。名前が長いときは 24 字で切る。
- Agent 本人の名前には Agent ごとに違う色を付け、同じ Agent はスレッドの中で同じ色にする。
- 野次馬の名前は「風吹けば名無し」とし、ID はランダムな英数字とする。
- スレタイは、最初のレスと一緒にモデルが作る（例:【悲報】ワイ、terraform plan が終わらない）。付けてから 30 分たったら、次のレスと一緒にモデルが付け直す。スレッドが 1 本で続くので、題を流れに合わせるためである。利用者の指示（2026-11-16）による。付け直しはレスの生成に相乗りし、モデルの呼び出しは増やさない。
- スレッドは常に 1 本で、Agent やタスクが替わっても同じスレッドに流れ続ける。自動では次のスレッドを立てない。利用者の指示（2026-11-16）による。
- レスの番号は 1 から増え続ける。保存するのは新しいほうから 1000 レスまでで、それより古いレスは落とす。
- スレッドが替わるのは、利用者が上端の「次スレ」ボタンを押したときだけである。前のスレッドは捨てる。

### 表示

```
【悲報】ワイ、terraform plan が終わらない              [実況中]
----------------------------------------------------------
1 sample-infra 2026/11/16(月) 19:32:10 ID:t17
  plan 回して 3 分経過、まだ refresh しとるンゴ

2 風吹けば名無し 2026/11/16(月) 19:32:41 ID:x8Kq2
  >>1 state でかすぎやろ

3 sample-infra 2026/11/16(月) 19:35:02 ID:t17
  【朗報】原因は環境変数の名前の打ち間違いと判明
```

- 上端にスレタイ、実況の停止と再開を切り替えるボタン、「次スレ」ボタンを置く。
- 配色は 2ch の定番（薄いベージュの背景、野次馬の名前は緑、スレタイは赤、アンカーは青）を既定にする。設定で Herdr のテーマの色に切り替えられる。
- 新しいレスが付いたら末尾まで自動でスクロールする。利用者が上にスクロールしている間は追従しない。
- Agent 本人のレスの名前か ID をクリックすると、その Agent に移る（`agent.focus`）。
- `mod.json` は `"place": "right"` とし、初回は右側に 1 つ出す。タブ内のペインや浮動ウィンドウとして置いても動く。

### レスを作るきっかけ

対象は `agents()` が返す端末で、状態が `working` のものと、状態が変わった直後のものである。

- 作業中の Agent の画面が前回から変わっていたら、その Agent のレスを作る。同じ Agent については 90 秒以上の間隔を空ける。
- 状態が `working` から `done` か `idle` に変わったら、完了としてすぐにレスを作る。利用者が見ている Agent は `done` を経ずに `idle` になるので、`idle` も含める。利用者が中断した場合も同じきっかけになるが、区別はモデルが画面から読み取る。
- 状態が `blocked` に変わったら、入力待ちとしてすぐにレスを作る。
- 画面が変わらないまま `working` が 3 分続いたら、待ちに触れるレスを作る。同じ待ちが続く間は、間隔を倍に延ばしていく。
- 雑談は、作業中の Agent が 1 つ以上あるときに限り、10 分に 1 回までとする。
- 作業中の Agent が 1 つもなく、状態の変化もないときは、モデルを呼ばない。
- mod のパネルが隠れている間（隠した列、別のタブ）も実況を続ける。あとで開いたときに、たまったレスを読めるようにするためである。止めたいときは上端のボタンか設定の `enabled` を使う。

画面が変わったかどうかは、スピナー、経過時間の表示、入力欄のような、内容と関係なく変わる行を除いてから比べる。

### 呼び出しの上限

- モデルの呼び出しは同時に 1 つとし、全体で 20 秒以上の間隔を空ける。
- 呼び出しは直近 60 分で 60 回までとする。このうち 10 回分は完了と入力待ちのために残し、進捗、待ち、雑談の呼び出しは直近 60 分で 50 回に達したら作らない。
- きっかけが重なったときは、完了と入力待ちを先に処理する。進捗と待ちは、最後のレスが古い Agent から処理する。
- 同時に作業する Agent は 1 つから 4 つ程度を想定する。
- 呼び出しが失敗したら、そのきっかけは捨てる。再試行はしない。失敗が 3 回続いたら実況を止め、上端に理由を出す。
- mod のコピーが 2 つ以上表示されていても、レスを作るのは 1 つだけにする。

### モデルへの入力と出力

入力は次の 4 つとする。

- 対象の Agent の画面の末尾（`hc read` の出力の末尾 4000 字まで）
- space と tab の名前、状態、作業が続いている時間
- きっかけの種類（進捗、完了、入力待ち、待ち、雑談）
- 直近のレス 10 件（アンカーを付ける先と、同じ話の繰り返しを避けるため）

出力は 1 件から 3 件のレスで、それぞれ投稿者の種類（Agent 本人か野次馬）と本文を持つ。書くことがなければ 0 件を返してよい。JSON で受け取り、形が合わないときは捨てる。

### 口調

プロンプトには次を書く。

- 猛虎弁で書く。一人称は「ワイ」、語尾は「〜やで」「〜やろ」「〜ンゴ」「〜やんけ」。「草」「サンガツ」「ぐう有能」「ぐう畜」「はえ〜」「せやな」「知らんけど」を使ってよい。
- 1 レスは 1 行から 3 行、長くても 120 字程度とする。
- 発見や知見は【朗報】【悲報】【速報】を付けて、何がわかったかを具体的に書く。識別子、コマンド、数値は画面のとおりに書く。
- 画面にないことを事実として書かない。感想と突っ込みは自由に書いてよい。
- 認証情報らしい文字列は書かない。差別的な表現、性的な表現、実在の人物への中傷は書かない。

口調の例はプロンプトに数件だけ添える。例をそのまま繰り返さないよう、直近のレスを入力に含める。

### 設定

`~/.config/herdr-nanj/config.json` に置く。ファイルがなければ既定値で動く。

| キー | 既定値 | 意味 |
|---|---|---|
| `enabled` | `true` | 起動時に実況を始めるか |
| `model` | `"haiku"` | `claude --model` に渡す名前 |
| `min_interval_sec` | `90` | 同じ Agent のレスの最短の間隔 |
| `max_calls_per_hour` | `60` | 直近 60 分の呼び出しの上限 |
| `chat_interval_min` | `10` | 雑談の最短の間隔。`0` で雑談なし |
| `palette` | `"classic"` | `"classic"` か `"theme"` |
| `exclude_spaces` | `[]` | 画面を読まない space の名前 |

### リポジトリの構成

```
mods/nanj/        mod 本体（main.js、mod.json、分割したモジュール）
RECIPE.md         herdr.dev/mods に載せるための説明
preview.png       スクリーンショット
README.md
scripts/          ~/.config/herdr-app/mods/nanj へ入れるスクリプト
```

- mod はビルドなしの JavaScript（ES モジュール）で書き、型は JSDoc と `.d.ts` で見る。
- 画面の差分の判定、きっかけの判定、呼び出しの上限、プロンプトの組み立て、出力の検証は、`herdr` モジュールに依存しない純粋な関数に分け、Node 上の vitest でテストする。パッケージ管理は pnpm とする。
- `main.js` は描画と、上の関数と `herdr` モジュールの橋渡しを受け持つ。

## 最初に確かめること

実装の最初に、次の 2 点を実機で確かめる。結果によって設計を直す。

- `claude -p` を、ツールなし、MCP なし、利用者の設定とフックなし、セッションの保存なしで呼べる引数の組と、1 回の応答にかかる時間。30 秒を超えるなら `exec` のタイムアウトを延ばす。10 秒を大きく超えるなら、間隔の既定値を見直す。
- gpui-kit で、行ごとに色の違う文字列と、末尾への自動スクロールを描けること。

## 作る側に任せること

- スレッドの保存先と、レスを作るコピーを 1 つに絞る方法（`shared`、`localStorage`、ファイルのどれを使うか）。条件は、mod の再読み込みとアプリの再起動のあともスレッドが残ることである。
- 内容と関係なく変わる行を見分ける規則の詳細。Claude Code と Codex の実際の画面で調整する。
- 認証情報らしい文字列を、モデルに渡す前に伏せるかどうかと、その規則。
- フォント、余白、色の値。
- 別のマシン上の Agent の扱い。動けば対象にし、動かなければローカルの Agent だけにする。

## 完成の確認

- `herdr-app check mods/nanj` が通る。
- vitest が通る。
- 実機で Agent を 1 つ動かし、進捗のレス、完了のレス、待ちのレスがそれぞれ付くことを `herdr-app shot` の画像で確かめる。
- 作業中の Agent がないまま 10 分置き、モデルの呼び出しが 0 回であることを確かめる。
- 実況中に、Agent の端末へ mod からの入力が届いていないことを確かめる。
